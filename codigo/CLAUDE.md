# CLAUDE.md

## What this is

RevitAutomation is a C# add-in for Revit 2023, 2024, 2025, 2026 and 2027 with a **single ribbon tab, «RevitAutomation»**. Each section is a panel with a pulldown: **CAD-REV** (the CAD→Revit engine, formerly «CAD MEP»: Tuberías, Conductos, Bandejas, Luminarias, Equipos y PCI), **Instalaciones** (Salas técnicas; Fontanería: Patinillo, Aislamiento RITE, Llaves de local húmedo), **Etiquetado**, **Documentación** (Planos; Exportar PDF/CAD) and **Región** (sectorización).
- `src/RevitAutomation` (`RevitAutomation.dll`) builds the tab (`RevitAutomationApplication.cs`) and holds the tools copied from the user's earlier RevitAutomation project (namespaces `RevitAutomation.Addin.Commands.*`, settings under `Documents\RevitAutomation\<tool>`). The CAD-REV buttons are thin subclasses in `Commands/CadRevCommands.cs`, so every button lives in `RevitAutomation.dll` (needed for the isolated load context in 2026/2027).
- `src/CadMepRevit` (`CadMepRevit.dll`) is the CAD-REV engine. `CadRevRibbon` (App.cs) supplies its five buttons. `ModelFromCadCommand.BuildWithoutUi` is used by Salas técnicas and runs with `BuildPlan.FollowCeiling = false`.
- The user's earlier RevitAutomation project (another folder) is the source of the copied tools. It must not be modified, and its old tools must not be brought in. See `docs/ESPEC_REVITAUTOMATION_PESTANA_UNICA_2026-11-25.md`.

## Build

From the project root in PowerShell, use the .NET 10 SDK with the .NET 8 SDK in the same .NET folder (2025/2026 and the engine tests use .NET 8). If it is not on `PATH`, point `DOTNET_ROOT` at its folder. `PREPARAR_PC.cmd` (`preparar_pc.ps1`) installs whatever is missing of the .NET 10 and 8 SDKs and Git (GitHub CLI only if the user answers that they will develop), through winget or the official direct links with a signature check.

```powershell
$env:DOTNET_ROOT = "$env:USERPROFILE\.dotnet"
& "$env:DOTNET_ROOT\dotnet.exe" build src/RevitAutomation/RevitAutomation.csproj -c Release -f net48 -p:RevitYear=2023
& "$env:DOTNET_ROOT\dotnet.exe" build src/RevitAutomation/RevitAutomation.csproj -c Release -f net48 -p:RevitYear=2024
& "$env:DOTNET_ROOT\dotnet.exe" build src/RevitAutomation/RevitAutomation.csproj -c Release -f net8.0-windows -p:RevitYear=2025
& "$env:DOTNET_ROOT\dotnet.exe" build src/RevitAutomation/RevitAutomation.csproj -c Release -f net8.0-windows -p:RevitYear=2026
& "$env:DOTNET_ROOT\dotnet.exe" build src/RevitAutomation/RevitAutomation.csproj -c Release -f net10.0-windows -p:RevitYear=2027
```

- `src/Revit.props` (imported by both add-in projects) maps the Revit year to the framework and API. 2023 and 2024 use .NET Framework 4.8 (`net48`); 2025 and 2026 use .NET 8; 2027 uses .NET 10. It references the installed Revit API, or else NuGet `Nice3point.Revit.Api.*` (`2023.4.0`, `2024.3.0`, `2025.4.60`, `2026.4.10`, `2027.4.0`), and checks the API major version. When building several years one after another, give each its own `IntermediateOutputPath`.
- On 2026-11-25 all three years built with **0 errors and 0 warnings**. In an offline shell, set process-local `NuGetAudit=false`.
- `Directory.Build.props` sets the C# language version, nullable reference types, implicit usings and shared assembly metadata. It disables SourceLink and source-control queries, which fail on the network drive.
- Keep ACadSharp at 3.8.35.
- **Revit 2023/2024 (net48):** write code against .NET 8 and the 64-bit ElementId API as before. `src/CadMepRevit.Core/Compat/NetFrameworkCompat.cs` (compiled only for net48, imported by a global using from `Directory.Build.props`) supplies missing BCL members with C# 14 extension members (`Math.Clamp`, `double.IsFinite`, `MinBy`, `GetValueOrDefault`, `Path.GetRelativePath`, `ProcessStartInfo.ArgumentList`…); PolySharp supplies language attributes; System.Text.Json comes from NuGet. Revit 2023 has no `ElementId.Value` or `new ElementId(long)`: use `RevitIds.FromValue(long)` (`src/CadMepRevit/Compat/RevitApiCompat.cs`). `RevitAutomationApplication` resolves the bundled dependency DLLs from its folder under net48. If a net48 build fails on a new BCL member, add it to the compat file rather than changing shared code.
- `instalar.cmd`/`desinstalar.cmd` generate the installer and run it (or its saved copy) silently. **Agents must never run either script or its PowerShell counterpart.** The same applies to `PREPARAR_PC.cmd`/`preparar_pc.ps1`, which install software for all users. `crear_instalador.ps1` only offers to run it when a SDK is missing and the console is interactive.
- The installer is `CAD-REVIT\Instalar_RevitAutomation.exe`, generated by `CREAR_INSTALADOR.cmd` (`crear_instalador.ps1`). Running that script is allowed: it runs all tests, builds the three years and packages them, but installs nothing. Test the exe only with `/destino:<scratch folder>`.
- Before installing, the installer removes the user's old RevitAutomation, its «CAD → Revit» module and the old CAD MEP, recognised by manifest id or class.

## Tests

`tests/CadMepRevit.Tests` is a console executable. All automated tests and plan comparisons run outside Revit.
Real drawings are optional and confidential. Copy them to a temporary folder outside the project, point `CADMEP_PLANOS` at it, and delete it afterwards. Pass a scratch directory under `obj` for generated DWG/DXF and slope reports, and keep the test's temporary files there as well.

```powershell
$env:CADMEP_PLANOS = '<temporary folder with DWG>'   # optional
$env:CADMEP_PRUEBAS = $env:CADMEP_PLANOS
$testScratch = Join-Path $PWD 'tests\CadMepRevit.Tests\obj\claude-test'
New-Item -ItemType Directory -Force -Path $testScratch | Out-Null
$env:TEMP = $testScratch
$env:TMP = $testScratch
& "$env:DOTNET_ROOT\dotnet.exe" run --project tests/CadMepRevit.Tests -c Release --no-build -- $testScratch
```

- **382 checks pass and 0 fail** (2026-11-25). `tests/RevitAutomation.Pruebas/<Tool>Harness` are console harnesses for the copied tools. They compile the pure-logic files only and print PASS/FAIL. `crear_instalador.ps1` runs them all. Tests tied to specific client drawings were removed for confidentiality. With `CADMEP_PLANOS` set, `SlopeTests.RunReal` and `PlacementTests.RunReal` also run on any DWG in that folder, whatever its name.
- `Program.cs` covers CAD reading, topology, dimensions and labels, DWF, inventory, performance, and error messages. Named groups cover `Slope`, `PipeFeature`, `Luminaire`, `Placement`, `Tray`, and `NetworkFitting`.
- `samples/*.dxf` supplies synthetic cases for tray fittings and pipe/duct fittings, gaps, and accessories. The suite also generates its own CAD fixtures.
- Before accepting a code change, compare the backup and the candidate across **all plans and all five buttons** with `tests/CadMepRevit.PlanComparison/Compare-Plans.ps1`.
- From the candidate, use `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/CadMepRevit.PlanComparison/Compare-Plans.ps1 -Antes <backup> -Planos <temporary folder> -AntesConUnionesActuales`. `-Calibrar` also prints gap and accessory calibration data.
- The comparison runs the actual core and `AutoPlanner` against the same simulated catalog. Review changes to classification, geometry, sizes, systems, slopes, fittings, and blocks. The script writes `Pruebas/FIRMAS_*_CODOS_TES_ACCESORIOS_20261119.json` in the candidate. These files contain drawing names, so delete them afterwards, along with the backup and the temporary drawings.

## Architecture

`CadReader` → optional DWF text and `LooseFixtures` → `AutoPlanner` → `CadPlacement` / `CadRegistration` → `MepBuilder` (`.Fittings`, `.Accessories`) → `ModelReport` → `%LOCALAPPDATA%\CadMepRevit\ultimo_informe.txt`.

### CAD-REV buttons (pulldown «CAD-REV»)

| Button | Current scope |
| --- | --- |
| Tuberías | Pipes, risers, sanitary fixtures and chambers, water equipment, and pipe accessories. Creates elbows, tees, and reductions. Reports four-way pipe encounters for manual resolution. Rolls back an individual fitting if it changes pipe slope. |
| Conductos | Ducts, elbows, tees, crosses, and reductions. Places grilles, diffusers, dampers, and air equipment at the associated run's elevation and orientation. |
| Bandejas | Cable trays and their accessories, with elbows, tees, crosses, and reductions. Electrical conduits are straight runs and their joints are resolved manually. |
| Luminarias | Lighting fixtures and controls. Recognizes fixtures drawn as lines and groups drawings by floor when applicable. Ceiling-mounted families use the ceiling or slab underside when found. |
| Equipos y PCI | Fire-protection, electrical, and miscellaneous device blocks, including electrical panel blocks. Panel layers used to identify equipment are excluded from run tracing. |

- Tuberías, Conductos, and Bandejas accept an optional DWF from the same plan. Apply CAD dimensions and size labels during planning. Pipe grades use `%` or `‰` labels, geometric arrows, and elevation references. Missing or conflicting slope evidence leaves affected runs horizontal. Without reference elevations, the highest axis uses a reported assumption of +2500 mm for suspended networks or −600 mm for buried networks.
- Small same-layer corner, tee, and inline gaps can be closed by extending axes within the size-based limits. Crossings and incompatible runs stay open. Inline accessories can split a run and connect both ends. A failed insertion or connection is rolled back, leaving the placed family and a report entry.
- Every button places runs, families, and markers over the linked or imported CAD using straight-line endpoints, circle centers, and top-level block insertion points. `CadPlacement` accounts for translation, rotation, and units and can link the drawing when needed. Review `Posición` in the report.

### Core (`src/CadMepRevit.Core`)

- `BlockInfo.cs` fits oriented CAD block footprints, resolves exported family/type names, and classifies block roles and chamber sizes.
- `CadModel.cs` defines geometry, drawing units, CAD records, and the entity inventory collected during reading.
- `CadReader.cs` reads model-space DWG/DXF through ACadSharp and extracts runs, blocks, circles, texts, dimensions, and leader geometry.
- `CadRegistration.cs` collects registration points and matches XY samples to estimate and check offsets.
- `DwfReader.cs` reads W2D text from DWF and aligns and merges it with CAD annotations.
- `LayerMapping.cs` classifies CAD layers into MEP kinds and supplies default sizes and heights.
- `LooseFixtures.cs` recognizes line-drawn luminaires and converts them into equivalent blocks for placement.
- `ModelInventory.cs` accounts for CAD entities and cross-checks created runs against input geometry.
- `ModelScope.cs` defines the five scopes, their allowed layers, blocks, and fittings, and default block elevations.
- `NetworkBlocks.cs` classifies scoped network blocks and finds a compatible run, attachment site, elevation, and direction.
- `NetworkBuilder.cs` cleans and joins axes, splits runs at branches and size changes, and classifies junctions.
- `NetworkComponents.cs` groups connected runs and samples points along a segment.
- `NetworkGaps.cs` proposes and validates short same-layer axis extensions and records rejected gaps.
- `Ocs.cs` converts DXF object coordinates to world coordinates, including mirrored geometry.
- `OutlineDetector.cs` derives axes and widths from parallel outlines, resolves ambiguous outlines, and handles fitting gaps and tray arcs.
- `PipeNetworks.cs` infers pipe service and material by connected network and ranks system and type choices.
- `PipeRisers.cs` plans vertical runs from concentric pipe circles, chooses levels and directions, and splits axes at in-line risers.
- `PlanDefaults.cs` holds shared automatic and wizard defaults and prepares layer geometry, units, and network inputs.
- `SizeAnnotations.cs` parses and associates dimensions and labels, propagates sizes along runs, and tracks conflicts.
- `SlopeAnnotations.cs` links slope labels, arrow geometry, and elevation references to pipe runs.
- `SlopeSolver.cs` votes on flow direction, computes shared node elevations, and reports conflicts and assumptions.
- `UserRules.cs` detects unknown items and stores office overrides for layers, blocks, and line-drawn fixtures in `%APPDATA%\CadMepRevit\reglas_reconocimiento.json`.

### Revit add-in (`src/CadMepRevit`)

- `App.cs` (`CadRevRibbon`) builds the five CAD-REV buttons and their generated icons for the RevitAutomation tab; it no longer creates a tab.
- `Commands/ModelFromCadCommand.cs` runs each scoped workflow, prepares the project, registers CAD, groups model edits, and produces the report.
- `Commands/ImportCadCommand.cs` retains the off-ribbon wizard workflow and writes the latest and dated reports.
- `Commands/HelpCommand.cs` exposes help and command availability classes. Help is off the current ribbon.
- `Config/PlacementConfig.cs` holds the active fixed-height setting and the inactive `bajo_forjado` rule.
- `Headless.cs` exposes a windowless build entry point for callers with a Revit `Document`.
- `Revit/AutoPlanner.cs` creates a `BuildPlan` from CAD, scope, defaults, and catalog, with geometry, sizes, systems, slopes, and block associations.
- `Revit/BlockFamilies.cs` loads matching or placeable generic families and records substitutions for CAD blocks.
- `Revit/CadPlacement.cs` finds or links CAD and derives the CAD-to-project transform using instance geometry and core registration.
- `Revit/CeilingFinder.cs` finds ceiling or slab undersides in the project and loaded links for ceiling-mounted families.
- `Revit/FamilyLibrary.cs` locates and loads `.rfa` files. `%APPDATA%\CadMepRevit\bibliotecas.txt` lists the local Revit library and any office libraries the user adds. Treat network libraries as read-only. The index is cached in `%LOCALAPPDATA%\CadMepRevit\indice_familias.txt`.
- `Revit/FittingSetup.cs` fills missing fitting assignments from existing or library families and maps drawn outer diameters to available nominal sizes.
- `Revit/MepBuilder.cs` creates and sizes runs, places families or `DirectShape` markers, transforms geometry, and collects build diagnostics.
- `Revit/MepBuilder.Fittings.cs` creates fittings in subtransactions, tries connector arrangements, and checks that pipe slopes survive fitting insertion.
- `Revit/MepBuilder.Accessories.cs` orients network families, splits runs for inline parts, and connects terminals and equipment with rollback on failure.
- `Revit/ModelReport.cs` reconciles the inventory and build result and formats model diagnostics, with a utility for saving reports.
- `Revit/RevitCatalog.cs` reads levels, types, systems, placeable symbols, and routing capabilities from the open document.
- `Revit/UnderSlabPlacer.cs` computes slab undersides and outer section heights for the retained placement rule.
- `Ui/ChoiceForm.cs` lists choices such as the CAD floor group.
- `Ui/LevelPickerForm.cs` selects the Revit level and also defines the progress window.
- `Ui/ImportForm.cs` maps layers and blocks and prepares a wizard build plan.
- `Ui/PreviewForm.cs` previews the wizard plan before model creation.
- `Ui/UnknownItemsForm.cs` asks the technician to classify unknown layers and blocks and supplies answers to `UserRules`.
- `Ui/Messages.cs` provides consistent dialogs with corrective steps.
- `Ui/HelpText.cs` provides the Spanish user help.

## Conventions

- Make recognition and geometry rules work for drawings from any office. Never tailor them to test filenames, exact layers, coordinates, or a single drawing.
- Use Revit API types, methods, and parameters that compile against both supported API versions. If an API call does not compile against the referenced version, treat it as unavailable.
- Take dimensions from the drawing or another identifiable source. Mark fallback values `SUPUESTO` in the report so the technician can review them.
- Keep all model edits for one ribbon invocation inside one assimilated `TransactionGroup` so one Ctrl+Z undoes the operation.
- Write ribbon labels, dialogs, reports, user guidance, and source comments in Spanish. Error messages must explain what failed and how to correct it.
- Report build results, offline tests or simulated plan results, and verification inside Revit as distinct evidence.
- Before editing code, make and verify a complete `robocopy` backup. The project contains paths longer than 260 characters.
- Work on a local copy. Write to the network project folder only to deliver finished work, when the user asks. Keep specifications in `docs/ESPEC_*.md`. Verification reports must not name client drawings.
- Ask the user whenever requirements or expected behavior are in doubt. Use the latest specifications and reports for current behavior. Section 4 of `TRASPASO_PROYECTO.txt` describes the 2026-11-12 version.

## Confidentiality

The user's test drawings and reports come from confidential projects. Do not keep copies of them, write their names, project codes, client names or people's names into code, tests, docs or reports, or save them to memory. Delete local copies, generated signatures and temporary outputs when done. Any example uses generic names.

## Ceiling rule and fallback fittings (2026-11-25)

- `PlacementConfig.PLACEMENT_RULE` is `sigue_techo`. Ducts, trays, conduits and horizontal pipes with an assumed elevation keep their top 100 mm below the slab above, including slabs in linked models. They step up or down with two elbows where the slab changes. Plan XY never changes, and CAD slopes and elevations are kept. See `docs/ESPEC_ALTURA_TECHO_Y_UNIONES_2026-11-25.md`, `Core/CeilingProfile.cs` and `Revit/MepBuilder.Ceiling.cs`.
- Fitting families are also found by name meaning (`Core/FittingNames.cs`), and `familias_uniones/*.rfa` is installed as the last-resort `Familias` library.
- When the backup already has `BuildPlan.AllowsFitting`, run `Compare-Plans.ps1` with `-AntesConUnionesActuales`.
- Not yet verified inside Revit.
